Event-driven data migration · Mar 2023 – Jan 2024

Teladoc Health

Node.js · Python · Apache Kafka · Protocol Buffers · MySQL

Context

Customers of the Livongo OneApp were being migrated to Teladoc Health. The migration needed a reliable way to confirm that user records arrived correctly across systems.

My contribution

  • Designed and implemented a Kafka-based reconciliation component covering 150,000–250,000 users or records.
  • Designed the workflow for eventual consistency, with idempotent Kafka consumers.
  • Added dead-letter queues for failed events and automated retries with exponential backoff.
  • Used Google Protocol Buffers for Kafka message schemas.
  • Designed daily reconciliation reporting against a target above 99.5% accuracy.

Engineering considerations

In a distributed migration, events can arrive late, twice, or not at all. Idempotent consumers, dead-letter queues, and backoff retries let the system recover safely, while daily reconciliation reports make any gaps visible.
